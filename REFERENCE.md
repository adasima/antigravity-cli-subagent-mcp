# REFERENCE — agy-mcp behavior reference

This document summarizes what each tool in `agy-mcp` actually does internally, allowing callers to understand its behavior accurately without reading the source code. Everything operates by invoking the Google Antigravity CLI (`agy`) behind the scenes, drawing from the user's AI Pro/Ultra subscription quota (zero metered billing). The tool suite currently consists of three tools: `agy_sub`, `agy_poll`, and `agy_diag`. Each tool is documented under the same framework: **Purpose / Arguments / Behavior / Return value / Notes**.

---

## 1. Overview — how requests flow

When Claude Code (or any MCP host) calls an `agy-mcp` tool, the server drives Antigravity through one of two execution paths:

- **Headless path** (text generation, trace reading, model list, quota retrieval): runs agy -p "<prompt>" without displaying a window. Closing standard input at spawn is an ironclad rule (leaving it open causes a silent, permanent freeze). Responses are read **stdout-first** (upstream bug #76 was fixed in agy v1.1.1), falling back to the conversation log (transcript) written by agy if stdout is empty or dirty. Timeouts are governed not by a fixed total wall-clock duration, but by a two-tier mechanism: a liveness/idle heartbeat timeout that triggers on inactivity, and a generous absolute ceiling (`timeout_s`).
- **Read-only slash commands** (quota = `agy_diag(action=live, what=quota)`): `agy -p /usage --output-format json` responds immediately without creating an agent turn, spending quota, or starting a conversation. The model list is fetched via `agy models`. Scraping the former interactive TUI (ConPTY) has been removed.

Tools that invoke agy control concurrency using an internal server lock (Semaphore) so that multiple runs do not execute at once:
- The `Inherit` MCP mode consumes one concurrent slot and runs in parallel (up to 10 concurrent runs).
- There is no exclusive execution that monopolizes all slots (`agy_diag(action=live)` also consumes 1 slot). Custom MCP (when `mcp` is specified) also consumes 1 slot, holding the write side of the **swap gate** (`RwLock`) only for a few seconds around spawn. This is because what must be protected is ensuring that another agy does not **start** during a swap, not the entire run (agy reads configuration only once at startup; see design-notes for measurements).
- When starting a new conversation, a temporary `spawn_gate` mutex serializes the new directory detection process, preventing directory misattribution even during concurrent runs.
- Trace and listing operations (`agy_diag(trace)` / `agy_diag(sessions)` / `agy_diag(status)` / `agy_diag(mcp)`) read files without invoking agy, consuming neither quota nor locks.
- Run-log aggregation (`agy-mcp stats`), cached quota (`agy-mcp quota`), waiting/collection (`agy-mcp wait` / `poll` / `jobs`), job specification inspection (`agy-mcp show <job_id>`), and server environment diagnostics (`agy-mcp doctor`) are **CLI subcommands**, not MCP tools. They primarily perform local file reads and diagnostics, so there is no reason to place them in the always-loaded schema (**live** quota retrieval remains as `agy_diag(action=live, what=quota)` because it logs readings to `quota_log.jsonl` and invokes agy inside the server's Semaphore).
- Because Claude Code launches a separate MCP server for each session, coexistence of multiple server processes is supported, and orphaned jobs left behind by parent process crashes are automatically detected and downgraded to LOST/FAILED.

## 2. Startup and prerequisites

- The agy CLI must be signed in with AI Pro/Ultra. If tokens expire, launching `agy` once interactively re-authenticates (headless mode cannot display authentication windows).
- The agy executable is searched in order: `AGY_BIN` -> default Windows install path -> PATH. Supplying `AGY_BIN` with a full path during registration is recommended.
- **Session startup status notice**: The server appends a single line of cached quota status to `instructions` (returned only once during `initialize`). Example: `agy quota (cached 38m ago): GEMINI ✗ weekly (resets in 1d9h) | CLAUDE AND GPT 5h 100% / weekly 13%`. For unexhausted groups, it outputs the remaining allowance per window, and when weekly consumption rate is based on 5 or more measured runs, `~N runs left this week` (prefixed with `⚠` if 10 or fewer). Reading the cache consumes neither quota nor latency. If the cache is stale, it is refreshed detached in the background during idle periods after `initialize` and reflected in subsequent refusal messages. **Tool descriptions are never changed mid-session** (they sit at the head of the caller prompt cache, and changing them invalidates all of it). Mid-session changes are communicated via refusal messages.
- **Startup health check**: Runs headless `agy models` (zero quota, ~2s, 15s timeout) on every startup, serving both to refresh the model cache and to verify system health. If the executable is missing or broken (e.g. upstream update failure), this call fails, producing AGY_DOWN: <reason> in `instructions`. Whether signed-out state is caught here remains unverified (`docs/todo.md`).
- **Protocol**: Under rmcp 3, responds to both legacy `initialize` and the 2026-07-28 version of `server/discover` (session-less, client information carried in per-request `_meta`). Antigravity (GUI, IDE, CLI; identifying as `antigravity-client`) communicates via the latter, so `initialize` never arrives. Consequently, roots are absent, and `workspace` in `agy_sub` must be specified explicitly. Client identity is obtained from request `_meta`. The server identifies as agy-mcp <version>.
- The working directory (workspace) does not depend on the host current working directory (cwd-less design).
  **`agy_sub` workspace never falls back to scratch** (preventing wandering and quota waste). Resolution order: explicit argument -> **client MCP roots** (retaining peer and roots capability during `initialize`, querying `list_roots()` only when the argument is omitted; single root accepted, **multiple roots produce an error listing them** — never picking arbitrarily) -> `AGY_WORKSPACE` -> **error**. Because roots are URIs, differences between `file:///C:/…` and `file:///home/…` are normalized by the pure function `root_uri_to_path` (unit tested). If the client does not support roots, `workspace` remains mandatory as before, with no regression. `agy_diag(action=status)` **actually runs this resolution and displays the result** (resolved path on success, workspace: REQUIRED — <reason> on failure; pure function `workspace_status_line`). Outputting the actual resolution result rather than the mere presence of roots capability is necessary because **clients may advertise capability but return nothing in `roots/list`** (measured 2026-08-15; furthermore, **the same client resolved normally in the subsequent session** = varies per session, so an `initialize`-time flag cannot track it). The `permissions:` permission mode is also output near the same line.
  Because agy has a quirk (bug) where simply switching cwd causes it to write files under its own scratch directory, appending `--add-dir <workspace>` at execution and prepending a mandatory absolute path directive `Work inside the project directory: <workspace> ...` (`prepend_workspace_directive`) to the prompt ensures that file edits take place within workspace.
  For tools where workspace is optional, if omitted, the environment variable `AGY_WORKSPACE` is used if set (designating the project root allows reusing target build caches for speed), otherwise the fixed `~/.agy-mcp/workspace` is used.

## 3. Ask tools (spending subscription quota)

Ask tools execute one autonomous agent run per call and return the **final report plus a token-frugal footer**.
The footer has the form ↳ [answer: <via> · ]N steps · wrote: <path (line count change)> · [also changed during run (no write receipt): <path> · [other jobs ran in this workspace meanwhile: jN, … · ]][⚠ eol changed: <path> CRLF→LF · ][⚠ ran "<cmd>" N times · ][⚠ stray artifacts left in workspace: <path> · ][<verify> · ]~Nk ctx · agy_diag(trace) for detail, displaying in a single line: the response source (`answer: stdout`/`transcript`, omitted if empty), step count, which files **this run itself** created/modified (with line count change from HEAD: `new, M lines` or `N→M lines`; file contents are omitted), git diffs lacking write receipts (if any) and other jobs that ran in the same workspace meanwhile, files whose dominant newline convention changed (CRLF→LF, etc.; excluding paths where git normalizes newlines — `.gitattributes` where `text` is set/auto — because they do not appear in commits and comparison with HEAD blobs produces false positives; determined via byte scan because Git Bash grep strips CR), wandering warnings when the same command was repeated 8 or more times, stray artifacts left by this run (`*.old`/`*.tmp`/`*_REPORT.md`/`tmp_*`, etc.; Python bytecode `__pycache__`/`.pyc` only when the run executed Python), preset `verify` verification results (only when configured), **estimated context size after execution** (`~Nk ctx` ≈ transcript bytes / 4, enabling callers to assess continuation trade-offs without calling `agy_diag(sessions)` separately), and an entry point to detailed traces. Background task results are truncated per line at a limit and collapsed when exceeding 5 items. When `cargo test` runs multiple test binaries, a single line summing each `test result:` line (`… (sum of N suites)`) is output (avoiding quoting only the `0 passed` of the final doc-tests).
Artifact paths originate from **success receipts** in the transcript ("Created file file://…", and "...changes were made by the (multi_)replace_file_content tool to: <path>..." indicating edits to existing files), ignoring failed writes and duplicates. Because agy 1.2.x writes these receipts and background task launch lines as **`GENERIC` entries** rather than `CODE_ACTION`/`RUN_COMMAND`, both are parsed. Since `GENERIC` has the same type as `view_file` results, an entry is treated as a receipt/launch only when the **first meaningful line** (`first_meaningful_line`) after skipping agy header lines (`Created At:`, etc.) begins with the marker phrasing (matching inside body text would turn viewed file contents into false writes or false pending tasks). agy internal bookkeeping files under brain (`implementation_plan.md`/`task.md`, etc.) are excluded from artifacts (not real work). Conversational answers without tool operations receive only ctx.
**`wrote:` contains only the transcript's own write receipts, never mixed with git diffs** (226092f). As before, `git status --porcelain -uall` is snapshotted before and after the run and diffed via `git_changed_paths`, but unioning the diff into `wrote:` as previously done caused edits by sibling jobs or caller sessions touching the same working tree concurrently to look like this run's achievements (real-world case: a job instructed not to touch `*.md` had markdown edits from another job appear in its `wrote:`, forcing the caller to suspect a violation and re-read all files). Therefore, diff paths that do not match receipts (`git_only_paths`, normalized across separators and Windows case via `norm_path_for_match`) are emitted as a separate segment also changed during run (no write receipt): <path>, and when that segment is non-empty, other jobs whose execution overlapped in the same workspace (`overlapping_jobs`, with running siblings treated as 'ending now or later') are named from the on-disk job mirror as `other jobs ran in this workspace meanwhile: jN, …`. This allows readers to judge whether a receipt-less diff is 'an edit by another job' or 'an edit performed by this run via shell (leaving no receipt)'. Writes outside the repository, such as `add_dirs` or reports directories, are invisible to git, so receipts remain the sole source of truth there. Status codes are trimmed before comparison, so a mere `git add` is not regarded as a 'write'. Snapshot fingerprints (mtime + length) are taken for **all paths**, tracked or untracked, so if a run modifies a file that was already ` M` before the run, it is still detected as a diff. In workspaces not managed by git, it evaluates to `None`, and `wrote:` gets `(no git — receipts only)` appended (explicitly indicating there is no working tree to compare against, avoiding misinterpreting a non-git empty diff as 'nothing was changed').

As a consequence of 'changes to workspace being visible via git diff', **investigation report files** for `preset=research` / `preset=report` are directed **outside the workspace** (`~/.agy-mcp/reports/`, auto-deleted after 30 days). The absolute path is substituted into `{reports}` in the preamble and added to the run's `add_dirs` to grant agy write permissions. Placing them inside the repository would make read-only investigation runs look like they 'modified something' every time, breaking the `wrote:` signal. This is not exposed as an argument (the caller lacks better decision criteria).

Furthermore, when a `preset=code` run reports 'done' but has modified nothing, `⚠ this task reported done but the workspace's git tree is unchanged — it may have punted (if this was a read-only investigation, ignore this warning and use preset=research)` is prepended to the response (detecting 'punts' where an agent stops after adding dependencies without writing implementations, `punt_evidence`). **It is never emitted if there is even one write receipt**. When receipts are absent, evidence is categorized into three types: non-git workspace (`it created/edited no files`) -> empty git diff (`the workspace's git tree is unchanged`, strongest evidence) -> diff exists but falls entirely within windows of overlapping jobs (naming the jobs and stating changes cannot be attributed to this run), and the message indicates which check triggered it. **When there are no receipts, diffs exist, and there are no overlapping jobs, the warning is intentionally suppressed** — this combination usually represents actual work editing the tree via shell commands without transcript receipts, not a punt. A known blind spot is that caller session edits during a run are not jobs and therefore not named, which can silence warnings for runs that did nothing.

Additionally, when there are jobs that exceeded inline wait time and became detached jobs (e.g., under `AGY_INLINE_WAIT`) whose results have never been collected via `agy_poll` (or CLI `wait`/`poll`) (`seen = false`), a `⚠ uncollected background job result(s)` banner is inserted at the head of the next `agy_sub`/`agy_diag(status)` call to prevent missed collections (targeting jobs completed within the last 30 minutes).

Ask tools consist of **a single tool: `agy_sub`** (consolidating former `agy_flash`/`agy_pro`/`agy_claude`/`agy_continue`).

### agy_sub

- **Purpose**: Delegate a single task to an Antigravity sub-agent (Gemini / Claude). The **sole entry point** for ask tools.
- **Arguments** (10 total): `prompt` (required) / `workspace` (optional only when the client provides a single MCP root, otherwise **required**) / `model`=flash (default)|pro|sonnet|opus|any model name / `model_label?` / `conversation_id?` (**short IDs accepted**; specify to continue, omit for new) / `add_dirs?` / `mcp?` / `preset?` / `force?` (default false) / `scope?`.
  - **Allowed write scope (`scope`)**: An array of path prefixes (workspace-relative or absolute, `{workspace}`/`{reports}` permitted). Any write receipts from this run falling outside the scope are output in the footer as ⚠ outside scope: <path>. It neither stops nor reverts execution (D13: agy cannot narrow paths within a workspace, and automatic reverts could destroy concurrent work). Evaluation is component-based (`src/core` does not match `src/core2/`), and case-insensitive on Windows. `~/.agy-mcp/reports/` is always in scope. Writes lacking receipts (written via shell, appearing in `also changed`) are not evaluated (cannot be distinguished from writes by other jobs). Passing this argument overrides the preset's `scope`.
  - **Nesting is not supported** (D17). An agy-mcp spawned by agy from CLI configuration exits before handshake under an agy spawned by the bridge (bearing `AGY_MCP_DEPTH`), and the run continues without it (agy retries a few times, gives up, and says nothing). `agy_sub` does not accept `nest` (ignored if passed). Sub-agents of the same model use agy's own sub-agents.
  - Because schemas represent an always-loaded cost across all sessions, **items with sensible defaults are not exposed as arguments**. To avoid an issue where Claude Desktop's Code tab rejects optional arguments carrying a `default` key with `expected nonoptional, received undefined` (claude-code#94718), `default` keys are stripped from properties under the schema (`strip_defaults`; actual default resolution is performed by serde default). Additionally, to accommodate behaviors where some MCP clients send null as a `"null"` string or send empty strings (claude-code#81911), each argument handler normalizes empty strings and `"null"` to unassigned (None) (`normalize_opt_arg`). `effort` / `gemini_ver` / `collect` / `max_answer_chars` / `timeout_s` have been removed (reducing `agy_sub` schema from 2704 to 1831 characters). Because effort and version are both **embedded in slugs**, explicit specification is consolidated at the end of the name (`model="flash-low"`, `model="gemini-3.7-flash-high"`) (text after the first TAB is auto-trimmed so that `<slug>\t<label>` output from `agy models` can be passed as-is). To circumvent an agy 1.1.5 bug (downgrades and effort drift on certain slugs #581), Gemini slugs are automatically converted to display label format (e.g. `Gemini 3.1 Pro (High)`) immediately before the CLI invocation and passed to `--model` (`wire_model`). `max_answer_chars` can be overridden via environment variable `AGY_MAX_ANSWER_CHARS`, and the ceiling via **`AGY_TIMEOUT`** (default 3600 seconds).
- **Behavior**:
  - **Pre-spawn refusal (spending nothing)**: Unless `force=true`, checks two conditions before spawn. (1) If the recent health check failed, re-checks immediately (~2s); if still failing, refuses with AGY_DOWN: <reason> (no restart required after fixing). (2) If the target model's quota group is at 1% or less in cache in **either weekly or 5h windows**, refuses. Freshness lasts until the parsed reset time if available, otherwise 4 hours. The first line of refusal is fixed: `AGY_UNAVAILABLE: <group> <weekly|5h|429> (<resets in …|seen … ago, reset unknown>) → model=<other>|none` (`<other>` is a concrete name looked up from the catalog, passable directly to `model`; when GEMINI is exhausted, newest Sonnet; when Claude/Argon quota is exhausted, newest Flash family; `none` if no destination exists in catalog). The weekly window is evaluated first (because once weekly quota exhausts, 5h values are not logged). `429` indicates the refusal is based solely on a 429 receipt with unknown window; `→ none` indicates the other group is also exhausted. Refusal does not occur if cache is absent.
  - **Running jobs in the same working tree**: If jobs are running in the same workspace (including those from other servers, excluding records where the owner process died), prepends a single line to the output: ⚠ same working tree as running job(s): jN "<prompt head>" (wrote: <paths written so far>) … ensuring awareness even if parallel lanes were omitted from the prompt.
  - **Model resolution**: Resolves labels for flash/pro/claude slots from cache (`~/.agy-mcp/models.json`) (default fallbacks: `gemini-3.8-flash` (medium), `gemini-3.1-pro` (high), `claude-sonnet-5-5` (medium), `claude-opus-5-5` (medium)). Selects the newest version for each slot and matches effort within that version (Claude also carries effort at slug end since 5.5). If a model for that slot is not found despite cache existence (e.g., during Google model name rotations), instead of hardcoding an old label, returns an error (hinting "run agy_diag(action=live, what=models)") (or can be specified directly via `model_label`). **`model` resolves aliases (flash/pro/sonnet/opus, case-insensitive) with highest priority**, resolving any other string as a **name** (`resolve_by_name`). `model_label` undergoes the same name resolution; if both are present, `model_label` wins. Priority order for name resolution: (1) exact slug match, (2) family name match (`family_key`: lowercased, trailing effort stripped, `.`, whitespace, `-`, parentheses collapsed to a single `-`; `gemini-4-argon` and `Gemini 4 Argon (Low)` are identical), (3) **exactly one lineage (family without version number)** containing all words in the name (`argon`, `sonnet`, `gpt-oss`). Once lineage is determined, selects newest version. If trailing effort is in the name, uses that effort strictly (if absent, rejects listing candidates of the same family); otherwise uses slot default (flash/Claude -> medium, pro -> high, slotless -> medium). Names matching two or more lineages are rejected listing candidates (`'claude' matches more than one model: …`); 0 matches return that it is not in the catalog alongside candidates of the same lineage. Both checks occur **before spawn**, re-fetching the list once before deciding if unmatched (passes the name through directly if cache is empty). Effort is a fixed value per model (**flash/sonnet/opus -> medium, pro -> high**). Slotless models (GPT-OSS, lite editions, unknown names) remain in the list and cache, selectable by name (not selectable by alias; GPT-OSS respects pre-refusal of CLAUDE AND GPT quota).
  - **Default model**: For fresh runs omitting both `model` and `model_label`, resolves via environment variable `AGY_DEFAULT_MODEL` (a setup-time configuration passed via registration `-e`, not a tool argument) if set (accepting aliases or names), otherwise via `flash` alias. If neither resolves, **does not guess**, refusing while naming catalog lineages and instructions for setting `AGY_DEFAULT_MODEL`. `agy-mcp doctor` outputs the value visible from that shell in a single line. Continuations do not use default models, preserving the conversation's model.
  - **Nonexistent `workspace`**: Refuses before spawn with workspace does not exist: <path> (because post-spawn OS error 267 appears as "agy not found").
  - **New vs continuation**: Without `conversation_id` = fresh (spawns with resolved model); present = resolves to full ID and resumes via `agy -p --conversation <id>`. **Model can be switched mid-conversation** by specifying `model` / `model_label` on continuation. **Continuations omitting model preserve the conversation's own model** (conversations other than Flash resolve that slot to current slug and pass `--model`; conversations with slotless models like GPT-OSS look up a slug of the same family (`family_key`) from the catalog using previous effort; otherwise agy silently downgrades to Flash; if absent in catalog, leaves it to agy as before). All runs explicitly passing `--model` (fresh, switched, model-preserving continuations) verify served_model receipts slot-wise (or by family name if slotless, only when starting with `gemini`/`claude`/`gpt`), appending `⚠ requested "X" but agy served "Y"` if mismatched (differences in effort or version ignored as noise).
  - **Flash context notification (neither refuses nor stops)**: For Flash runs where estimated ctx exceeds `flash_ctx_limit()` (`AGY_CTX_LIMIT`, default 100,000 tokens ≈ transcript bytes / 4), appends a single warning sentence: `⚠ this conversation is now ~Ntok …`. Emitted pre-execution on resume (`ctx_warn`, when that conversation is already large), post-execution when grown during run (`ctx_over_note`). **Former behaviors of 'refusing resumes of heavy Flash sessions' and 'forceful termination during run (`StopReason::CtxCap`)' were removed on 2026-09-10** — preempting quality risks at the expense of discarding finished work was an unfavourable trade-off. The notice **does not name migration target models** (degradation with long contexts affects all models, and migration is not a cure). It only advises starting fresh in a new conversation with a brief handover summary if behavior deteriorates, and is silenced by `force=true`. Does not appear outside Flash. Separately, across all models, if estimated ctx of a conversation on continuation exceeds ~200k (empirically measured input ceiling), appends `⚠ session ctx ~Ntok exceeds the ~200k measured input ceiling` (does not refuse; when both trigger, only Flash notice is displayed).
  - **Liveness/Idle timeout**: Initiates `start_kill` after inactivity reaches `AGY_IDLE_TIMEOUT` seconds (default 180 seconds, adjustable via environment variable). Liveness monitoring watches SQLite WAL mtime (e.g. `<id>.db-wal`, updated each turn; `transcript.jsonl` is not used for liveness as it can remain empty on write errors). A generous ceiling (default 3600 seconds, environment variable `AGY_TIMEOUT`, not an MCP argument) functions as an **absolute ceiling** not extended by liveness. Because callers are unblocked by inline wait (described below), this ceiling is calibrated against 'the longest execution worth running to completion' rather than 'human patience'. When stopping (idle, ceiling, quota wall), terminates not only agy.exe but also descendant processes (shell -> tools) spawned by agy (Windows job object). Descendants of runs that exited on their own are not killed. When stopping on idle/ceiling, records state immediately before stopping (last step, count of unfinished background tasks, active shells) as a single line in job record `last_step`, stderr, and `~/.agy-mcp/stops.jsonl` (without extension).
  - **Early stopping at quota wall**: After retrying 429 (`RESOURCE_EXHAUSTED`) with backoff up to ~8 times, agy **goes silent without exiting**. Because each retry writes `ERROR_MESSAGE` to transcript and advances liveness, quota walls previously surfaced only after 10-17 minutes of idle timeouts. Currently, when **consecutive** 429 retries at transcript tail (`trailing_quota_retries`, resetting to 0 if interrupted by other entries like 503 capacity errors) reach `AGY_QUOTA_RETRY_CUTOFF` (default 3, `0` disables), agy is stopped (`StopReason::QuotaWall`). Even with partial answers, it is treated strictly as failure (Err/exit 1) rather than completion (Ok/exit 0) (`stop_forces_failure`; partial answers retained as context). Failure messages begin with `QUOTA_EXHAUSTED:` and include the string `RESOURCE_EXHAUSTED (code 429)` so `record_quota_wall` continues to recognize it. If cached observations for the other quota group are not exhausted, names that group's model (`opus` for Gemini wall, `flash` for Claude wall) as an alternative.
  - **Build completion wait and automatic summary continuation**: Recovers cases where agy turns commands like `cargo build` into background tasks, replies only with "building...", finishes its turn, and exits. Reads task logs on disk `.system_generated/tasks/<task-id>.log` directly, analyzing summary patterns and termination markers for test runners including Cargo, Jest, Vitest, pytest, cargo test, etc., to judge pass/fail and exit codes (`read_task_log_result`). Because agy SYSTEM_MESSAGE notifications are unreliable, direct log reading is the sole ground truth. Upon task completion, if agy's final reply was merely a waiting message (`is_wait_only`), or if disconnected without a final report due to agy's `--print-timeout` or idle/hard-cap cutoffs (`is_cut_off`, excluding QuotaWall; even without a single line of answer, advancing steps triggers this handling: `stopped_without_answer`), the bridge automatically launches a single summary continuation (`· auto-resumed for a summary after a cut-off run`) in the same conversation, prompting the model to report changes, verification results, and unfinished items. Background task results appended to the return count only the final outcome per command; if all ok, outputs a single line `bg: N tasks (M runs), final all ok`; if failures remain, outputs those lines (up to 5) alongside the ok count line (single line as before if only 1 task).
  - **Dispatch**: All runs are registered and detached as jobs. Default inline wait is **per-client**, determined by client name reported during `initialize` (pure function `client_inline_wait`): **`local-agent-mode-*` (Claude Desktop) returns `job_ack` at 45 seconds, `antigravity-client` (Antigravity GUI, cutting off calls at 180 seconds, measured 2026-10-29) returns `job_ack` at 150 seconds**; all others **wait until completion and return results directly**. Rationale for the former comes from measurements — this surface marks requests as `Request timed out` at ~60 seconds, and none of `MCP_TOOL_TIMEOUT` (set to 1 hour), `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`, or progress notifications prevented it (2026-08-15, 4 arms; details in design-notes). Because only the **request** timed out while the job kept running, no work was lost, but to avoid paying 'unexpected error + manual collection' each time, it explicitly acks ahead of the wall. Overridable via `AGY_INLINE_WAIT=<secs>`, with `0` meaning "never ack". Runs converted to ack are collected via `agy_poll` (defaults to most recent) or `agy-mcp wait`. The ack text reads `started agy_sub job jN (running in parallel | at the concurrency limit — waits for a free slot). NEXT ACTION REQUIRED: run in the background NOW: agy-mcp wait jN …`, instructing background waiting without polling via MCP.
    In-flight progress notifications (`notifications/progress`, every 15 seconds) are sent **only when `AGY_PROGRESS=1`** (default off). Because needed to prevent 30-minute idle terminations on clients that honour notifications, the code is preserved.
  - **Presets (`preset`)**: Prepends preamble text to prompt, enforcing boilerplate rules even on brief goals. Built-ins: `none` (default) / `code` / `research` / `report` / `review`, backed by `src/presets/builtin.toml` (parsed with the same TOML code as user presets, preventing drift). Layered with last-wins precedence: built-in -> `~/.agy-mcp/presets.toml` -> `<workspace>/.agy/presets.toml`. Keys: `preamble` / `extends` (parent preamble precedes, child flags win) / `expects_changes` (arms punt nudge) / `needs_reports_dir` (permits writing to `{reports}`) / `verify` (safe build/test verification command executed in workspace by bridge itself after sub-agent run succeeds; results collapsed into footer) / `agent` (runs fresh runs only under agy custom agent via --agent <name>; agy restricts tools to agent's `tools:`; built-in `research` uses `agy-mcp-research` (read, search, and `write_file` only; no shell or edit tools); bundled definitions rewritten before run to ~/.gemini/config/agents/<name>.md; omitted on resume as conversation retains agent tools; MCP tools cannot be narrowed, so disable via `mcp` argument if needed; names up to 64 chars of alphanumeric, `-`, `_`) / `scope` (default allowed write scope; same format as `scope` argument above, inherits from parent, child overrides; built-in `research` sets `{reports}` only) / `expect_files` (paths of files expected to remain after successful run; workspace-relative or absolute, `{workspace}`/`{reports}` permitted; missing files output to footer as ✗ expected file missing: <path>; checked every time regardless of git diff; inherits from parent, child overrides; unused by built-ins) / `env` (environment variable map passed to child processes and `verify` command; used for `CARGO_TARGET_DIR` isolation across parallel lanes; reserved names `PATH`/`PATHEXT`/`COMSPEC`/`PSMODULEPATH`/`SYSTEMROOT`/`RUSTC_WRAPPER`/`RUSTC_WORKSPACE_WRAPPER`/`CARGO_BUILD_RUSTC_WRAPPER`/`AGY_*` and multiline values rejected; bridge internal variables always take precedence). Substitutions: `{workspace}` and `{reports}`. **Unknown names error listing known presets**, unparseable files **error with filename and line number**, and unknown keys are rejected (`deny_unknown_fields`), never silently dropping preambles. Available names listed by `agy_diag(action=status)`. Overriding is **entry-level rather than field-level** (use `extends` to add incrementally). Default `none` is also a normal entry, so redefining it affects all plain requests.
    Because `verify` is executed by the bridge itself, it passes the same safety checks (`is_safe_command_segment`) as sub-agents, restricted to **a single segment** (chaining disallowed). Because preset files arrive with cloned repositories, this prevents the bridge from executing commands that would be denied to sub-agents. Checked at resolution time (before spending quota). Skipped if git confirms the run modified nothing. Timeout capped by `AGY_VERIFY_TIMEOUT` (default 120 seconds). Programs resolved via PATH × PATHEXT, launching `.cmd`/`.bat` (npm/yarn/pnpm/npx) via `cmd /c`. Dedicated message returned if missing (due to preset file error). On Windows, if `rc.exe` is absent from PATH, appends bin\<version>\x64 from newest Windows SDK (preventing panics in build scripts like `tauri-winres` calling `rc.exe`; SDK absent from PATH of servers started by clients).
  - **MCP scoping (`mcp`)**: Controls MCP servers available to sub-agents during execution. Replaces global configuration only. Files `.agents/mcp_config.json` and `.agents/skills/` inside workspace are read by agy even headlessly; because the bridge does not modify workspace trees, they remain active even under `mcp=none` (noted in return message). Omitted/`"inherit"` = retains agy current configuration, `"none"` = grants no MCP servers (clean, fast, safe), comma-separated server names (e.g. `"context7,Zenith"`) = that subset only. Because agy lacks per-run MCP flags, bridge backs up, swaps, executes, and restores shared config `~/.gemini/config/mcp_config.json` (RAII `McpGuard`; see §5 for double-swap prevention). **Restoration is moved forward to when agy is demonstrably up** (appearance of conversation directory for fresh runs, advance of liveness for continuations). Measured 2026-08-14: restoring at directory appearance (4.72s / 4.95s) maintained scope, whereas a **fixed 5.0-second delay** leaked server lists on slower runs — rationale for tracking initialization signals rather than fixed delays. If signals do not arrive in time, restoration is not advanced, falling back to Drop restoration at run end (`restore` is idempotent).
- **Return value**: Final report + footer (showing cumulative artifacts/ctx on continuations). Brief job ID message if exceeding inline wait under `AGY_INLINE_WAIT`.
- **Notes**: To avoid Windows `CreateProcess` argument length limits (32767 chars), returns an error before spawn if total assembled command line exceeds ~30K characters (recommends attaching files as workaround).

### agy_poll

- **Purpose**: Retrieve status and results of runs that exceeded inline wait time and became jobs (e.g. under `AGY_INLINE_WAIT`).
- **Arguments**: `job_id?` (defaults to most recently started job).
- **Behavior**: Looks up in-memory job table, falling back to reading **disk mirror** (`~/.agy-mcp/jobs/<id>.json`) if absent, enabling collection even across server restarts. If `job_id` is omitted and multiple jobs exist, prepends a count line of other jobs (`Other background job(s): N`) to the latest job result.
- **Return value**: `job jN [tool] running/done/FAILED …`. Running lines display request prompt beginning (caller prompt, not preset preamble; `(resume: <model>)` for plain resumes), most recent tool call step and elapsed time (e.g. `now: run_command: cargo test (12s ago)`), and if 3 or more timestamped steps exist, pace calculated from the median of the last 5 steps (`· ~10s/step`), distinguishing steady progress from stalls. Because agy activity is mirrored to records every 30 seconds, stalled jobs display `⚠ NO agy activity for Ns` (same in `agy-mcp wait`/`jobs`). Running lines end with `(poll again later)`, but while watched by `agy-mcp wait`, this becomes `` (a background `agy-mcp wait` is watching it — no need to poll; …) ` (wait places its PID in ~/.agy-mcp/jobs/<id>.waiter, counting only while alive).
- **Notes**: Actually receiving terminal results sets `seen`, stopping uncollected banner nudges. Because `seen` resides on the **disk record**, collecting via `agy-mcp wait`/`poll` in separate processes also silences nudges.
- **Waiting in background via CLI**: The same binary also serves as a CLI with `agy-mcp wait [<job_id>...]` (blocks until completion, exit 0 = all completed / 1 = at least one failed / 2, zero quota spent), `poll`, `jobs`, `show <job_id>` (displays saved dispatch spec and recovery steps), and `doctor` (self-diagnostics of server PID, environment, and job mirror status) subcommands. Running `agy-mcp wait` as a background task on the host collects results without wasteful MCP polling. If `--timeout` is omitted, dynamically waits up to each job's own execution ceiling (`AGY_TIMEOUT`, default 3600s + 600s grace) rather than a fixed 1800s (explicit `--timeout` remains legacy fixed deadline). For jobs lost due to server stops (LOST), outputs recent activity (`last seen: <last_step>`) and partially written files recorded in write receipts (`written before the stop (may be half-done): …`, up to 8 items, only those updated after job start).
- **`wait` with `job_id` omitted**: Waits for **all** pending jobs (running + uncollected completed) belonging to cwd's workspace (prioritizing `AGY_WORKSPACE` if set) (`--all` unbounds scope). Resolved roster is output to stderr even if single; if scope is empty, names jobs remaining in other workspaces. Targets all jobs rather than 'latest single' because under parallel dispatch (up to `AGY_MAX_CONCURRENT`), launching 3 `wait`s after fanning out 3 runs would cause all to watch the same job.
- **No dispatch in CLI**: `wait`/`poll`/`jobs`/`show` only read disk mirrors; because quota, concurrency, and MCP scope reside in the server, there is no dispatch path from outside MCP. When a session lacks `agy_*` tools, use `agy-mcp doctor` to diagnose the cause. Because job records are the order form itself (full prompt, workspace, add_dirs, preset, mid-run `conversation_id`), jobs that crashed with their host server can be resumed from failure instructions (one-line resume and `agy-mcp show <id>`).

## 4. Diagnostic and informational tools (spending no quota)

### agy_diag

- **Purpose**: Retrieve various diagnostics and information. Consolidates the former 6 diagnostic tools (agy_status / agy_mcp / agy_trace / agy_sessions / agy_stats / agy_live; `stats` moved to CLI `agy-mcp stats`).
- **Arguments**: `action` (required, `status`|`mcp`|`trace`|`sessions`|`live`) / `conversation_id?` (for trace) / `full?` (for trace) / `limit?` (for sessions) / `what?`=quota|models|both (for live, default **quota**).
- **Behavior of each action**:
  - `status`: Bridge health check. Uses only `agy --version` and file lookups to inspect version, data directory, currently selected model, permission mode (`permissions:`), available presets, and the actual resolution result of `workspace`. Even if the latest transcript is empty, if that conversation belongs to a job rejected by the permission gate (rejection recorded in failure message), it is treated not as a problem but as `ok` with a note. Displays count of readable skills and paths to skills whose frontmatter is malformed causing agy to drop them silently (while broken skills exist, a warning is also appended to `agy_sub` returns; judged strictly by shapes verified to drop in real measurements).
  - `mcp`: Inspect list of MCP servers available to agy itself (the sub-agent side). Parses `~/.gemini/config/mcp_config.json` to list enabled/disabled registered servers. Also lists servers from `.agents/mcp_config.json` in workspace.
  - `trace`: Inspect sub-agent work process compressed to 1 line per step for token savings (`full=true` adds thought prompts `↳ think:`).
  - `sessions`: List recent conversations to provide continuation decision criteria (context size, etc.). Returns short ID, elapsed time, step count, estimated context size, prompt beginning (skipping workspace boilerplate directive prepended by `agy_sub`), etc. (`limit` caps count). Short IDs can be passed directly to `agy_sub`.
  - `live`: Refresh 'true subscription remaining quota' or 'model list' (argument `what`). All return within seconds with zero quota spent.
    - `quota`: Reads `remaining_fraction` and `reset_time` (ISO) for each bucket from `agy -p /usage --output-format json` (`parse_usage_json`); reset time is measured. If the balance of `/credits` is greater than 0, adds an `AI credits:` line. Results are saved to `quota_log.jsonl` and used to calculate burn rate in `agy-mcp stats` / `agy-mcp quota`. Burn rate aggregates all snapshot pairs in a 24-hour window, **completely excluding intervals where 5h quota recovered**, and displays "not enough measured runs" without numeric values if measured runs are fewer than 5 (extrapolating from small samples produced misleading numbers in actual measurements).
    - `models`: Retrieves model list from headless `agy models` subcommand (zero quota, no TUI, ~2s), saves it to `~/.agy-mcp/models.json`, and updates model resolution source for ask tools. Outputs 1 line per family (`gemini-4-argon : low·medium·high [pro]`), showing effort variations and which model aliases currently resolve to (`[flash]`, etc.). If multiple versions exist in the same family, newest is marked with `(newest)`. Slotless models appear in the same format.
    - `both`: Sequentially executes `live_quota()` (`/usage`) and `live_models()` (`agy models`).

**Because the quota cache refreshes automatically, callers never need to decide when to invoke `live`.** Two mechanisms populate `quota_log.jsonl` automatically: (1) `record_quota_wall`: when a run fails with a 429 receipt (`RESOURCE_EXHAUSTED` / `code 429` / `[429]`, including `QUOTA_EXHAUSTED:` failures from the 3-retry cutoff above), it records a 0% snapshot for that model's group (the receipt itself is an authoritative observation, so there is no need to re-read `/usage`; the next dispatch is pre-refused). The group is determined from the requested model, falling back to the conversation's own served model (`resolve_quota_group` / `read_conv_model`) for bare resumes without `--model` (otherwise nothing can be learned from a bare resume 429). The recorded wall includes an alternative hint naming the other group's model if that group is not exhausted. (2) `maybe_refresh_quota`: called after completion of each run (after releasing permits), reading `/usage` in the background **only when the latest observation is older than 30 minutes and one permit can be acquired via `try_acquire_owned`**. Using `try_` instead of `await` is essential: waiting for a permit would delay the next real dispatch, so if unavailable, it silently gives up (retrying upon next run completion). However, an old observation ceases to justify a refusal as soon as it contradicts new facts: (a) a subsequent run in the same group succeeded (judged by `ok` in `runs.jsonl`; percentages are never fabricated), (b) `/usage` was read but that group was absent (logging `"missing"` and displaying `⚠ GEMINI row not found in usage screen`), or (c) the recovery time (`reset_time`) read from `/usage` has passed. The recovery time is also displayed in refusal messages, `agy_diag(live)`, and `agy-mcp quota`. Immediately after a run fails with 429, freshness checks are bypassed to read `/usage` and obtain a record with a recovery time. This logic applies identically to both 5h and weekly windows.

**`agy-mcp quota`** displays the latest reading per group with elapsed time, appending time until reset for groups whose weekly quota is exhausted. The burn line has the format `weekly -1.10%/run (~1 runs left this week) · 5h -6.71%/run (~0.11%/1k ctx) · ~N runs left in 5h (rolling)`. **`agy-mcp stats`** outputs only a summary of `runs.jsonl` (counts per model, success rates, median and p90 for steps/ctx/duration), grouping rows by **requested model** (failed runs lack a served model, so grouping by served would split one model into separate success and failure rows). A block showing divergence rates between requested and served models is also output.

## 5. Key points of common mechanisms

- **Closing standard input**: Headless `agy -p` silently hangs immediately after launch if stdin remains open, so it must always be spawned with stdin closed.
- **Fixing `PATHEXT` before spawning**: agy appends `.CPL` to its own `PATHEXT` before passing it to child shells; when spawned from an MCP server that inherits no `PATHEXT`, the child shell gets only `.CPL`, rendering bare command names like `cargo` unresolvable (creating a paradox where `where.exe` finds it via its own internal logic). `pathext_fixup` prepends the default list only when `.EXE` is missing.
- **Reading responses stdout-first**: Because #76 (nothing emitted to stdout) was fixed in agy v1.1.1, there are two tiers: **stdout** (system tags stripped) -> `PLANNER_RESPONSE` in the transcript if stdout is empty, dirty, or failed. Former SQLite byte scanning has been removed; when the transcript cannot be read either, it does not fill with guesses, but produces an error naming agy's own recorded `ERROR_MESSAGE` receipt (e.g. 429 quota wall).
- **Headless permission gate (agy 1.1.3+)**: Tools requiring confirmation are soft-denied in headless mode. Writes are resolved by the bridge auto-granting `write_file(<workspace>)` in settings.json's `permissions.allow`. Shell commands permanently merge safe routine commands (build/test suites and toolchain discovery) into `config.json`'s `globalPermissionGrants` as `regex:` rules at startup; if a rejection still occurs, `auto_grant_rule` auto-grants only mechanically verifiable rules and resumes the same conversation (budget: 4 rounds). Chained commands with `;`, `&&`, or `||` are broken into individual segments and granted **only when all segments are safe**; pipes, redirects, and `powershell -Command` wrapping are always excluded. Unrecoverable rejections are reported as messages originating from agy's stderr. Pre-granted regexes are a **fast path** rather than the policy itself; the authoritative policy is `is_safe_command_segment` (the inclusion relationship that any line matching a regex must pass the policy is pinned by tests). The policy rejects only verbs that reach outside the checkout: publishing to registries, credential manipulation, and installing to PATH (`cargo install`, npm `-g`). Lines falling outside pre-grants incur a single round-trip recovery cost to pass, so **future new subcommands are never permanently blocked**. When the environment variable `AGY_PERMISSIONS=trusted` (or `AGY_DANGEROUSLY_SKIP_PERMISSIONS=1`) is set, the server enters Trusted permission mode, passing `--dangerously-skip-permissions` to bypass the permission gate.
- **Failure reports describe progress made up to that point**: Even in dead runs, completed steps remain in the transcript, so `progress_note` appends before the failure: <step summary> · wrote: <files> and `run_core` appends changed on disk: <path> from post-run git snapshots to the error (in failures, diffs cannot be cross-checked against receipts and cannot be attributed to this run, so overlapping jobs running during the window are named as well). The status remains failed (exit 1 for `agy-mcp wait` is unchanged); only the reported content changes.
- **Naming corrupted images**: When agy crashes with a non-zero exit code without a receipt (`AGY_ERROR`), image paths mentioned in the prompt (`.png`/`.jpg`/`.jpeg`/`.webp`/`.gif`, absolute or workspace-relative) are inspected for matching magic headers and trailers (PNG's `IEND`, JPEG's `FF D9`, GIF's `3B`, WEBP's RIFF length). If a mismatch is found, an image that may not decode: <path> line is added to the error. Unreadable paths are skipped. This is because agy silently exits with code 1 on undecodable images (`docs/multimodal-notes.md` §3).
- **Artifacts are paths only**: File paths are collected from success receipts (creation of new files, edits to existing files; `GENERIC` in agy 1.2.x, `CODE_ACTION` in older versions), excluding internal bookkeeping files under brain. `wrote:` contains only these receipts, while receipt-less git diffs are output separately as `also changed during run (no write receipt):`.
- **Quota is read from slash command JSON**: `agy -p /usage --output-format json` (zero quota, instant response, cwd-agnostic). Group names in JSON (`Gemini Models`) are uppercased and stripped of trailing ` MODELS`, aligning to `GEMINI` / `CLAUDE AND GPT`. Running manually from Git Bash turns `/usage` into a path due to MSYS path conversion and sends it as a prompt to the model (spending quota), so execute from PowerShell.
- **Rotation safety of dynamic model resolution via slot abstraction**: Models are handled via abstract slots (default fallbacks: `gemini-3.8-flash` (medium), `gemini-3.1-pro` (high), `claude-sonnet-5-5`, `claude-opus-5-5`), falling back to static consts if the model cache is empty. If the corresponding slot is not found, it re-fetches the list via `agy models` (headless, zero quota, ~2s) and **re-resolves on the spot once**, erroring only if still not found. To avoid agy 1.1.5 bug #581, Gemini slugs are automatically converted to display label format (e.g. `Gemini 3.1 Pro (High)`) before being passed to `--model` (`wire_model`). The cache is also automatically refreshed at startup (when empty, >24h old, or in legacy label format). In addition to aliases (flash/pro/sonnet/opus), models can be specified by name (`argon`, `gemini-4-argon`, or slugs) (`resolve_by_name`; text after TAB is auto-trimmed). When agy rejects an old slug remaining in the cache with `invalid model selection` (zero quota), the list is refreshed on the spot, adding a hint to the error that repeating the same call will resolve against the current list.
- **Concurrent execution and exclusive locking**: Concurrent execution via `Semaphore` (maximum 10). Inherit-mcp and custom-mcp consume 1 permit and run concurrently (custom-mcp holds the write side of `swap_gate` only for several seconds around spawn). There is no exclusive execution (`agy_diag(action=live)` also takes 1 permit). Fresh conversation detection is serialized by `spawn_gate`.
- **Job conversion and multiple server coexistence**: All runs are registered and detached as jobs, recorded in memory and disk mirrors. By default, they wait synchronously until completion; when `AGY_INLINE_WAIT` is specified, runs exceeding inline wait time return a job_ack, collectible via `agy_poll` or CLI subcommand `wait` (progress is reported via MCP progress tokens on long runs). Execution continues to completion even if the caller disconnects. Coexistence of multiple server processes is managed, and orphaned jobs whose parent process disappeared are automatically detected and downgraded.
- **Double swap prevention (McpGuard)**: When temporarily swapping MCP configurations, if `.agyswapbak` already exists, swapping is skipped and execution runs under Inherit to prevent losing original settings through nested swaps.
- **Direct task log fallback (`read_task_log_result`) and automatic summary continuation for build tasks**: Does not rely on agy's SYSTEM_MESSAGE, directly reading `.system_generated/tasks/<task-id>.log` to judge pass/fail using summary patterns and termination markers from test runners like Cargo, Jest, Vitest, pytest, etc. If the final answer at task completion is only a waiting message, an automatic 1-turn summary continuation (`· auto-resumed for summary`) is executed.

## 6. Known caveats

- **Workspace automatic trust registration**: In untrusted directories, agy prompts on first run "Trust this folder?", which cannot be answered in headless mode, resulting in exit 0 and an empty transcript. To prevent this, `run_agy` calls `ensure_workspace_trusted` before spawn, automatically registering workspace (and each add_dir) into the `trustedWorkspaces` array of agy's trusted list `~/.gemini/antigravity-cli/settings.json` (pure merge `merge_trusted_workspace` / `process_settings_json` is unit-tested, atomic write via temp+rename, **never overwrites files that fail to parse**, deduplicated case-insensitively on Windows). Best-effort; the run continues even if this fails. An empty transcript is not necessarily a trust issue (see cross-drive bug below; auto-trust does not fix that).
- **Cross-drive transcript bug (agy-side, non-`C:` drives) and automatic bridge workaround**: agy (v1.0.11) fails to write `transcript.jsonl` when cwd/workspace is on a different drive (e.g. `G:`) than user home (`C:`) (measured 2026-06-25). A path without a drive letter like `/Users/<you>/...transcript.jsonl: The system cannot find the path specified` appears in cli.log — because on Windows, a leading `/` path resolves to the **root of the current drive**, so cwd on `C:` succeeds while `G:` searches `G:\Users\...` and fails. Because the model round-trip completed and **file edits landed successfully on physical disk**, even if an empty transcript reports 'failed', **the work is often complete (verify with git diff)**. **Workaround (implemented 2026-06-25, `agy_cwd`)**: `run_agy` anchors cwd to a stable directory on the home drive (`~/.agy-mcp/cwd`) when workspace is on a different drive than home, ensuring driveless transcript paths resolve to real locations. The actual workspace is passed via `--add-dir` plus absolute path directives as usual, so file edit targets remain unchanged (drive detection via unit-tested `is_cross_drive` / `drive_letter`). When agy fixes this upstream, setting `AGY_NO_CROSSDRIVE_WORKAROUND=1` reverts cwd=workspace for verification.
- **Windows command line length limit**: An error is returned before spawn if the total assembled command line exceeds approximately 30K characters. For long prompts, attach files and use add_dirs as a workaround.
- **Avoiding duplicate MCP swaps**: If `.agyswapbak` exists, swapping is skipped and execution proceeds with Inherit.
- **Flash context notification**: A warning sentence is appended when estimated ctx exceeds 100K tok (`AGY_CTX_LIMIT`) in Flash. **It neither refuses nor terminates forcefully** (removed 2026-09-10). It does not name a migration target model, encouraging starting fresh with a new conversation instead. Silenced by `force=true`.
- **Punt nudge**: In presets where `expects_changes = true` (in built-in presets: `code`, and presets that `extends` it), if write receipts are zero, a warning banner `⚠ this task reported done but … — it may have punted` is attached. Evidence is categorized as: outside git / git tree unchanged / diffs entirely within windows of overlapping jobs; if there are diffs without receipts and no overlapping jobs exist (treated as real edits via shell), the warning is not emitted.
- **Early failure at quota wall**: When consecutive 429 retries reach `AGY_QUOTA_RETRY_CUTOFF` (default 3), execution fails immediately with `QUOTA_EXHAUSTED:` without waiting for idle timeout, naming a model from the other quota group as an alternative if available. If the cached reading indicates the window, a `window: <group> weekly (resets in …)` line is also attached. `QUOTA_EXHAUSTED:` is a failure **after spending** 429 retries; `AGY_UNAVAILABLE:` is a refusal before spending.
- **Concurrency is per-process**: `AGY_MAX_CONCURRENT` is per server process, so N sessions can run up to N-fold concurrently. The real limit is quota.
- **Uncollected job warnings**: If there are uncollected jobs within 30 minutes of completion, a `⚠ uncollected background job result(s)` banner is displayed on the next call. Because all collection paths (`agy_poll`, inline returns, CLI `wait`/`poll`) set `seen` on disk, collecting in another process does not cause false warnings.
